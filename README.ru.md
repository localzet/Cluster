# Localzet Cluster

[English documentation](README.md)

Кластеризация Localzet Server с архитектурой Gateway/Business Worker: шлюзы обслуживают соединения клиентов, воркеры выполняют обработчики приложения, Register распространяет адреса шлюзов.

## Совместимость

- PHP 8.2 и новее; для многопроцессного режима Unix нужны `pcntl` и `posix`.
- Текущие исходники и ближайший выпуск требуют `localzet/server:^7.0`.
- Требуется PHP 8.2 или новее; для многопроцессного режима Unix нужны `pcntl` и `posix`.

## Установка и пример

Пакет пока не зарегистрирован в Packagist. Добавьте Git-репозиторий и установите стабильный выпуск:

```sh
composer config repositories.localzet-cluster vcs https://github.com/localzet/Cluster
composer require localzet/cluster:^1.0
```

Для примеров и регрессионных тестов из этого репозитория:

```sh
composer install
export LOCALZET_CLUSTER_SECRET="$(php -r 'echo bin2hex(random_bytes(32));')"
php start.php start
```

На всех узлах должен быть один секрет, хранящийся вне Git. Примеры отклоняют отсутствующий секрет и строки короче 32 байт. Регистратор и WebSocket по умолчанию слушают loopback; клиентский адрес — `ws://127.0.0.1:7273`.

Команды управления: `php start.php stop`, `restart`, `reload`, `status`. Обработчики приложения находятся в `Events.php`; адаптируйте пример под своё приложение.

## Компоненты

- `Register` аутентифицирует шлюзы и воркеры, распространяет адреса шлюзов.
- `Gateway` принимает соединения клиентов и маршрутизирует сообщения.
- `Business` поддерживает соединения со шлюзами и вызывает обработчики приложения.
- `Client` отправляет сообщения клиентам, пользователям и группам.

Для нескольких серверов настройте доступные `registerAddress`, `lanIp` и непересекающиеся диапазоны портов шлюзов. Внутренние порты должны быть доступны только доверенным узлам. Общий секрет не шифрует трафик: нужна доверенная приватная сеть или защищённый транспорт. Примеры демонстрируют локальный запуск, а не готовую production-конфигурацию.

## Проверка

```sh
composer validate --strict
composer lint
composer test
```

Регрессионные тесты используют локальные пары сокетов и проверяют рассылку адресов, загрузку классов, отказ при неверной аутентификации и отсутствие секретов в логах на Server 7. CI независимо разрешает зависимости для PHP 8.2–8.5. Тесты не подтверждают отказоустойчивость между хостами или production-нагрузку.

### Десериализация пользовательских объектов

Cluster передаёт тела сообщений и сессии в PHP-формате `serialize()`. По умолчанию входящие PHP-классы не создаются при `unserialize()`: массивы и скалярные данные продолжают работать, а сериализованные пользовательские объекты декодируются как `__PHP_Incomplete_Class`. Если кластер изолирован, все узлы взаимно доверенные и пользовательские сессии действительно содержат объекты, включите `localzet\Cluster\Protocols\Cluster::$allowObjectSerialization` на каждом узле. Не включайте эту настройку для узлов, которым нельзя доверять.
